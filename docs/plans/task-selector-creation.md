# Task selector and creation adaptation

Status: superseded implementation proposal. Prepared 2026-11-18. The final implementation differs from this proposal: it creates directly from the current query with Shift+Enter, has no preview/title field or create button, and does not require an inspection acknowledgement after uncertain creation. See docs/verification/task-selector-creation.md for source and automated verification notes.

## Recommendation and scope

Adapt TaskNotes' rich selector appearance and search-to-create interaction into our existing `TaskPickerModal`. Own a static result renderer and creation adapter; retain our `filterAndSortTasks`, public bridge, staging controller, idle-card persistence, and modal lifecycle. Do not import TaskNotes' internal modal, task-card renderer, NLP parser, settings, or mutation helpers.

Use public `nlp.parse` plus `tasks.create` for creation in the same picker. Show a parsed preview and an explicit **Create and stage** or **Create and add** button; Shift+Enter invokes that action. This supports title prefilling, batch continuation, cancellation, and known task identity. Keep Enter for selecting an existing result. Creation must never start a timer.

The alternative, invoking the native Create new task command through `TaskCreationCoordinator`, supports the full TaskNotes form but currently closes our picker, cannot pass its query as a title, and has no completion/cancellation result suitable for resuming a batch. Its event/DOM observation is not a reliable identity contract for an improved selector. Retain it for existing independent callers if any remain; do not use it as an automatic fallback inside this picker. When public inline creation is unavailable, selection still works and the creation footer explains the missing capability. A separate full-form integration can be revisited if TaskNotes exposes a public modal API.

## User-visible behavior

| Action | Timers: Add task | Staged: + |
| --- | --- | --- |
| Select existing | Persist one idle card, then close after acknowledged success | Stage, hide that path, retain query/focus and keep open |
| Create | Create note once, persist idle card, then close after acknowledged success | Create note once, stage it, hide its path, retain query/focus and keep open |
| Destination failure | Keep picker open with Retry add for the existing note | Keep picker open with Retry stage for the existing note |
| Escape/cancel before submission | Close without writes | Close without writes; previously successful batch choices remain |
| Blank input | Show eligible tasks; creation disabled with Enter a task title | Same |
| No matching result | Keep preview/create action available for valid input | Same |

Rich rows show title, status, priority, contexts, tags, projects, due/scheduled dates and optional subtask completion count. Preserve the informational Pomodoro marker. Metadata is display-only: clicking/tapping anywhere on a row selects it; status icons do not toggle completion, and project/title chips do not navigate. Use safe text DOM creation, accessible labels, scoped `tntp-picker-*` CSS, wrapped metadata and truncation without horizontal overflow. Retain existing date/context formatting where appropriate; date-only values must not shift through UTC conversion.

Keep `filterAndSortTasks` ranking unless a separate search change is requested. Stage candidates exclude archived, completed and reserved/already-staged paths; hide successful paths immediately and refresh eligibility on relevant changes. Revalidate before writes because the snapshot can become stale. Preserve existing Timers eligibility rules. Multiple staged choices before the same `beforePath` remain in selection order; test A then B produces A, B, anchor. A removed anchor follows the controller's documented fallback and reports any warning.

Up/Down and Enter select results. Shift+Enter creates only when preview is valid and ready; ignore composing IME events. Tab reaches the explicit create/retry controls, and Escape closes. Do not steal plain Enter when no result exists. Provide a visible button on touch devices, clear busy state, polite error announcements and focus restoration. If a created task retains the query, show its success and prevent accidental repeated creation from the unchanged draft; editing the query enables a new creation. Repeated identical titles may be intentional, so this is an operation guard, not global title-based deduplication.

## Creation data and defaults

Add a pure adapter from parsed data to a minimal creation payload. Send explicit parsed values only, allowing TaskNotes to apply its own status, priority, folder, template and other creation defaults. Use `creationContext: "modal-inline-creation"` only after contract/runtime verification of its folder behavior; otherwise use the supported `api` default and document that difference. Do not read private settings or reproduce its defaults locally.

Map title and the user-supplied parsed `status` and `priority` values; omit status/priority when absent so TaskNotes defaults apply. These are top-level parsed fields, as confirmed by the inspected upstream `buildTaskCreationDataFromParsed.ts` lines 19–20 (not nested metadata). Pin their optional string shapes in contract tests before implementation; the imported NLP-core declaration is not installed in this checkout. Map dueDate plus optional dueTime to due; scheduledDate plus optional scheduledTime to scheduled; contexts; projects; tags; details; recurrence; positive estimate to timeEstimate. Adapt/test the upstream date/time and tag normalization rules without importing their dependency tree. Preserve local date strings and time precision. Omit absent fields instead of sending empty arrays or empty strings that overwrite defaults. Do not supply timestamps or guessed status/priority values.

Map parsed `userFields` IDs through public `catalog.userFields()` to `customFrontmatter` property keys, using upstream-compatible value conversion (the inspected helper joins array values with comma-space). Block creation with a specific explanation if parsed custom values cannot be mapped; never silently discard them. Do not copy the picker search metadata or staging properties into creation defaults. TaskNotes applies registered defaults; the staging controller subsequently writes its own registered staging fields. Warn explicitly if creation defaults yield a completed/archived task that cannot be staged: retain the created note and do not repeatedly create it.

Public `parseInput` can manufacture `Untitled Task` when no semantic title remains, while native selector uses `parseInputForModal`. The missing-title symbol is private. Validate trimmed input and parsed title, show an editable title in the preview, and require explicit title confirmation/edit whenever parser output is a placeholder or otherwise ambiguous (including metadata-only input). Do not use private symbols or guess that a placeholder means the user intended that title. The actual submitted title must be visible and nonblank.

## State, failure and performance contract

Represent creation and destination separately: idle, parsing/preview, creating, created-awaiting-destination, routing, succeeded, retryable-destination-error, creation-error/uncertain. Keep the returned TaskInfo/path as the identity. A destination retry must never call tasks.create again. Add explicit outcomes to `IdleCardStore.add`: added-and-saved, already-represented, unavailable, invalid/full, or failed/unsaved. Its current void return and caught save error cannot prove success. Preserve deduplication by normalized path, and allow saving the same in-memory membership again after a failed persist. Do not close or show success solely because a promise resolved.

Serialize creation with the shared write mechanism and a plugin-wide busy guard; do not hold that queue while awaiting a staging action that also needs it. A mutation correlation ID aids diagnostics; it is not an idempotency guarantee. If creation fails after a possible write and no task identity is known, report uncertain creation, refresh once, and require inspection before another create attempt. Do not blindly retry note creation. Returned tasks, rather than unrelated global task.created events, determine routing.

Use modal-open generations and bridge-connection generations for every deferred operation. Closing, unloading, reconnecting or switching destination invalidates UI callbacks. Once submission has started, Escape can close the UI but cannot cancel a completed vault write: suppress later automatic destination writes if the owning session is gone, and notify that the created note remains available. Never delete a created task to simulate rollback. Recheck destination and task eligibility immediately before routing. Do not reopen a closed picker after completion.

One task/status snapshot per opening; local search per keystroke. Debounce parsing (about 150 ms), discard stale previews, and submit only the preview for the exact current query. Clear caches on close/reconnect. Coalesce task-change refreshes; no timer-tick-triggered reads. Optional subtasks: only fetch for rendered rows, at most 4 requests concurrently, cache by normalized path for the opening, cap at 100 cached parents, cancel queued work on close/query change, and invalidate affected entries on task changes. Missing capability or read failure omits the count rather than showing zero. Count summaries only; no recursive fetches or full subtask cards.

## Implementation sequence and file ownership

1. **Public contracts and bridge.** Extend `src/tasknotes/runtime-api.types.ts`, `src/tasknotes/TaskNotesBridge.ts` and `COVERAGE.md` with trimmed optional NLP/create/relationships types and capability-plus-function checks. Explicitly add optional `catalog.priorities()` types/wrapper, gated by `catalog.read`, for priority labels/colors: upstream returns `PriorityConfig[]` with value, label, color, id, weight and optional icon; vendor only the fields rendered. Read once per opening. If unavailable or an unknown value is encountered, render the raw priority value with neutral styling; validate color values before applying them and test missing catalog/method, unknown values and malformed colors. Add bridge wrappers, connection guards and normalized errors. Preserve connection readiness when optional features are absent. Extend `tests/contract.test.ts`, bridge tests and `tests/fakes/fakeGateway.ts`. Record tested runtime versions.
2. **Pure models and creation state.** Add `src/model/taskCreation.ts` for validation/mapping and `src/state/PickerCreationController.ts` for one-shot creation, known-path destination retry, and shared busy/lifecycle handling. Wire it in `src/main.ts`; dispose on unload. Add explicit add outcomes in `src/state/IdleCardStore.ts` with targeted tests. Keep staging through `src/state/StagingController.ts`; change it only if existing outcomes cannot express required retry or anchor behavior.
3. **Owned rich rows.** Add `src/ui/TaskPickerRow.ts` and a bounded `src/state/TaskPickerRelationships.ts` cache. Replace MarkdownRenderer task-chip enhancement in `src/ui/TaskPickerModal.ts` with static rows. Reuse existing metadata helpers where safe, add scoped `styles.css` rules and focused renderer/cache tests. Do not copy TaskNotes TaskCard or its settings/mutation/i18n dependencies.
4. **Integrate selector and creation.** Update `TaskPickerModal.ts` to own query/preview, explicit create/retry action, batch acknowledgements and keyboard behavior. Update `src/ui/TimerPaneView.ts` to route both selected and created tasks through the same acknowledged destination adapter with beforePath preserved. Remove the old picker command handoff and redundant created-task routing; retain/remove `TaskCreationCoordinator.ts` only after checking all callers. Extend modal, view, idle-card and staging tests.
5. **Attribution and packaging.** Add `THIRD_PARTY_NOTICES.md` with the complete TaskNotes MIT copyright/permission/warranty text, exact source revision, adapted files and modifications. Preserve our own license. Update `esbuild.config.mjs` to embed the full upstream notice in the production/development JS banner so normal Obsidian/BRAT three-file installs retain it; add the notice as a release asset in `.github/workflows/release.yml` and copy it in dev assets. The current workflow ships only main.js, manifest.json, styles.css, so a repository-only notice is insufficient. Include an upstream notice comment in adapted CSS if CSS is copied. Verify minification retains notices.
6. **Verification and documentation.** Run focused tests, then `npm run check`. Build generated main.js according to repository convention only after source checks pass. Document the supported public API behavior, disabled-feature messages and test evidence. No release, real-vault deployment, commit or push is part of this plan.

Steps 1 and 2 precede integration; row work depends on the relationship contract; packaging precedes shipping. Keep existing dirty planning configuration and local/debug/cache artifacts untouched.

## Acceptance and validation

Automated coverage must demonstrate selected and created routes, stage batch A/B ordering, query/focus retention, successful-path exclusion, no timer start, duplicate-click/Shift+Enter protection, persistence failure retry without second creation, unknown creation failure, missing optional capabilities, mapping/default omission/custom-field conversion, metadata-only/placeholder titles, date-only/time formatting, stale parse/relationship results, close/unload/reconnect during creation, and no leaks or per-tick reads. Test task eligibility changing between search and selection and completed creation defaults. Use deferred promises for races, not only synchronous fakes.

Visual UAT uses the guarded repository dev-vault and hidden CDP sandbox through existing `uat:start` tooling. Do not reset or deploy into Personal Vault. Verify the actual loaded TaskNotes version and capability methods before fixtures. Exercise existing and created tasks in both entry points, empty/no-match search, long metadata, dark/light themes, narrow pane/modal widths, keyboard and simulated touch targets, native focus behavior and restart persistence. Inspect written task metadata, idle membership and unchanged timeEntries to substantiate no timer start. Inject creation and destination failures where feasible. Record screenshots and actual outcomes separately from source inspection; physical mobile/touch behavior remains unverified unless observed on a real device.

Completion means both flows work with acknowledged destination persistence, rich rows remain safe and readable, optional API absence degrades gracefully, attribution survives the shipped assets, and the targeted/full checks and guarded UAT pass. No unresolved product decision blocks this recommendation; the creationContext/default and placeholder-title differences are explicit implementation compatibility checks, not reasons to copy private APIs.
